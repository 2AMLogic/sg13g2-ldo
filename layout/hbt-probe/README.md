# layout/hbt-probe — SG13G2 HBT extraction/LVS witness (issue #150)

A reproducible, vendor-fixture probe that witnesses the **upstream bipolar
recognition gap** in klayout-tools' curated `sg13g2` deck: the deck declares
no bipolar device class at all, so the IHP `npn13G2` HBT unit testcase
extracts with **zero devices**, and an LVS compare against the vendor's own
reference netlist mismatches with device counts **layout 0 / reference 3 /
matched 0** (observed `error_count` 15).

This is diagnostic evidence **outside the T1 manifest**: it changes no
circuit, no ratified spec, no design decision, and no T1 verdict. It exists
because the canary's BiCMOS purpose (root `README.md`, "BiCMOS is a real
difference") calls for an HBT extraction witness — this fixture is the first
committed layout on this block that exercises a bipolar device at all, and it
does so precisely to expose what the tool chain cannot yet do with one.

## What is vendored here

| File | What it is |
| --- | --- |
| `npn13G2.gds` | IHP's own LVS unit-fixture layout: one cell `npn13G2`, three HBT instances (`le=900n`, `we=70n`, multiplicities 1/2/4), DBU 0.001 um. Unmodified. |
| `npn13G2.cdl` | The matching vendor reference netlist: three four-terminal `Q<C> <B> <E> sub!` cards with `m=1/2/4`. Unmodified. |
| `LICENSE-IHP.txt` | The IHP-Open-PDK Apache-2.0 license text (attribution for the two files above). |
| `validate_fixture.py` | Fixture content validator (GDS: single `npn13G2` cell, DBU, documented bbox; CDL: the three Q cards). Guards against malformed input masquerading as a tool gap. |
| `hbt_probe.py` | The probe: `--record` / `--check` / `--run` (below). |
| `lvs_request.json` | The exact `klt lvs` request the raw LVS report was produced from (pre-extracted layout netlist vs vendor CDL, `sg13g2` deck, plain-element reference form). |
| `expectations.json` | The pinned contract: tool/deck pins, fixture hashes, license hash, permitted exit codes, expected verdicts, upstream mapping. |
| `raw/` | The committed raw `klt drc` / `klt extract` / `klt lvs` JSON reports, byte-for-byte as the pinned build wrote them. |
| `summary.json` | Deterministic normalized summary derived from the raw reports; regenerated byte-for-byte by `--check`. |

**Provenance.** Both fixture files are byte-identical to
[IHP-GmbH/IHP-Open-PDK](https://github.com/IHP-GmbH/IHP-Open-PDK) commit
`5e6d592e4002946a4616f798c357f0f3c06cf3b6`, paths
`ihp-sg13g2/libs.tech/klayout/tech/lvs/testing/testcases/unit/bjt_devices/{layout,netlist}/npn13G2.{gds,cdl}`
(sha256 pins in `expectations.json`). The terminal labels and geometry are
the vendor's; nothing was redrawn, rewired or added. This is one unit
testcase, not a transistor sweep, and not a vendor-runset verification.

## Pins

The probe is pinned to the same build layout-check CI already installs:

* **klt** `0.8.0` — PyPI release, tag commit `c572046be644e0407f693f2410f3abb799d68a3a`
  (`KLAYOUT_TOOLS_VERSION` in `.github/workflows/ci.yml`). The pin is
  enforced before every tool run; any other build is refused.
* **KLayout** `0.30.12` — the resolved engine recorded in every raw report
  (`provenance.klayout_version`). This build warns on every run that it was
  *tested* against `0.30.10`; that upstream disclosure is preserved
  deliberately (`pins.klayout_tested_version`), and the engine actually used
  is pinned and recorded rather than left floating.
* **Deck** `sg13g2`, content hash
  `sha256:894326a4e37fb24fef2f7ffc6ae1da55a0e262b0f0bc1c09adc4862909278fda` —
  re-verified from every fresh report's `provenance.deck.content_hash`.

The signoff grader runs on the same release (`KLAYOUT_TOOLS_VERSION`), but is
not touched by this probe.

## Modes

```bash
python3 layout/hbt-probe/hbt_probe.py --run      # fresh gap witness (needs the pinned klt)
python3 layout/hbt-probe/hbt_probe.py --record   # refresh raw/ + summary.json (pinned klt)
python3 layout/hbt-probe/hbt_probe.py --check    # offline stored-evidence validation (stdlib only)
```

* **`--run`** validates the fixture, freshly runs
  `klt drc` / `klt extract` / `klt lvs` in a temporary workdir, verifies the
  klt/klayout/deck pins **and** the pinned expected verdicts, and prints the
  witness. A changed verdict, an unexpected error, or any pin drift fails
  loudly, names [klayout-tools#2864](https://github.com/2AMLogic/klayout-tools/issues/2864),
  and never rewrites the baseline.
* **`--record`** is `--run` plus an explicit baseline refresh: only when every
  pin and expected verdict held are `raw/` and `summary.json` rewritten. Any
  error leaves the committed baseline untouched.
* **`--check`** is the offline gate (CI-runnable with nothing but stdlib):
  re-hashes every committed input, re-parses and chain-checks the raw reports
  (drc/extract input hash → GDS pin; extract `netlist_sha256` → lvs
  `environment.layout_sha256`; lvs `reference_sha256` → CDL pin), re-verifies
  every tool/deck pin, re-checks the committed verdicts against
  `expectations.json`, and regenerates `summary.json` **byte for byte**.

**What `--check` claims, and what it does not:** it attests the freshness and
internal consistency of the *stored* evidence — that the committed reports,
request and fixture are untampered and still summarize to the committed
summary. It does not re-run any tool and does **not** establish that the tool
gap still persists on your installed build; that is `--run`'s job.

**Hard failures, never expected-gap success:** missing `klt` binary, pin
drift, invalid JSON, klt error envelopes, missing/empty fixture, missing top
cell, and non-permitted exit codes (drc/extract must exit 0; lvs must exit 3
— mismatch *is* the expected verdict here).

## Expected outcomes (verified on the pinned build)

| Stage | Verdict | Meaning |
| --- | --- | --- |
| `klt drc` | `clean`, 0 violations | Within the curated deck's **incomplete** coverage: 12 rules checked, 31 skipped (upper-metal stack the fixture doesn't draw), 9 stream layers with no deck rules — all disclosed in `summary.json → observed.drc`. **Not** a full-deck DRC signoff. |
| `klt extract` | `extracted`, 0 devices | `device_classes` carries nfet/pfet/caps/resistors/antenna — **no bipolar class** — so none of the three vendor HBT instances is recognized. |
| `klt lvs` | `mismatch`, devices 0/3/0, 15 errors | The direct LVS consequence of the extraction gap against the vendor reference. |

## Upstream mapping (and non-claims)

* The extraction recognition gap is attributed at the **aggregate** level to
  [2AMLogic/klayout-tools#2864](https://github.com/2AMLogic/klayout-tools/issues/2864).
  The per-model limitations #2860/#2861/#2862 are *described there*; this one
  fixture does not independently reproduce each of them.
* **#2688 is NOT reproduced here** (DRC behavior; this fixture is DRC-clean
  and no expected false positives are asserted).
* **#2952 is NOT established here.** The attempted transformed reference in
  subckt-call form errors with `reference netlist has no top circuit` on this
  pin; the probe treats that error as a hard failure, never as a known gap.
* Any *new* genuinely observed tool gap goes through the friction protocol
  (file/verify against the klayout-tools tracker) before this baseline is
  touched.

## Re-recording the baseline

Only after an upstream-verified, deliberate behavior change:

```bash
uv venv /tmp/hbt-probe-venv
uv pip install --python /tmp/hbt-probe-venv/bin/python "klayout-tools==0.8.0" "klayout==0.30.12"
PATH="/tmp/hbt-probe-venv/bin:$PATH" python3 layout/hbt-probe/hbt_probe.py --record
python3 layout/hbt-probe/hbt_probe.py --check
```

`--record` rewrites `raw/` and `summary.json` only when every pin and
expected verdict held; the commit must carry a provenance note naming what
moved upstream.

## CI

The `layout-check` job runs, after the existing flow check: `--check`
(offline) + this directory's tests, then `--run` (fresh) — both on the
already-installed pinned build; no PDK install is needed for these vendored
inputs. The PDK-free `characterization-report` job picks the same test file
up through its existing `layout` test discovery; tool-backed cases skip there
with a named reason.
