# Batch-backend validation: `exclude` and `--variant-lines` (issue #64)

This run checks the two `batch_backend.py` changes the dynamic DoE needs.
The checks compare the backend with itself on the fleet. The local-ngspice
equivalence is in `../20261010-025044/`.

1. **Sparse corner sets use `exclude`.** The DoE's four corners
   (`ss`/125C/`res_bcs`, `ff`/-40C/`res_wcs`, `ss`/125C/`res_wcs`,
   `ff`/27C/`res_bcs`) are not a process x temperature cross product.
   Before this change the backend split such a set into one request per
   temperature. Now the set stays in one request, and the eight unwanted
   pairs go into klt's `exclude` list. The 0.5.0 runner honours `exclude`:
   every per-deck report below has `corner_count` 4.
2. **`--variant-lines '^(Iload|Cout|Resr) '`.** The 384 DoE decks differ only
   in their `Iload`/`Cout`/`Resr` lines. The backend now moves those lines,
   verbatim, out of the body and into each point's own `corners.lib`
   section, after its model cards. That lets all operating points of one
   bench share a single request, with one corner per point. SPICE does not
   depend on element order, so the circuit should not change. This run
   checks that it does not.

## Why (2) was needed

The first campaign attempt submitted one request per operating point:
96 requests of 4 corners each, at `SWEEP_BATCH_CONCURRENCY=6`. Each job
simulated for about 25 s (`elapsed_seconds` in `per-deck/*/report.json`) but
took about 12 min end to end on the shared fleet, because each job waits
for and boots its own Spot instance. That rate meant several hours for the
grid. The attempt was stopped after 4 of the 96 requests had returned. Those
4 are kept here as references, and their netlist snapshots were not
committed. This friction is filed generically upstream as a comment on
klayout-tools#2725 (no design-parameter axis).

## Method

- Decks were generated by `run_sweep.sh --doe-generate --batch` through
  `gen_netlist` (`SWEEP_BATCH_PLAN_ONLY=1`, so the decks were written but
  nothing was submitted). The design netlist and templates are those of
  commit `3058282`.
- **Per-deck references** (`per-deck/`): one request per operating point,
  4 corners each, with no `--variant-lines`. Five requests are kept: loop
  gain at 0 mA/0.33 uF/0 ohm, 0 mA/1 uF/0 ohm and 1 mA/1 uF/0 ohm (the last
  one is `smoke-*`), and PSRR at 0 mA/0.33 uF/0.5 ohm and 0 mA/1 uF/0 ohm.
  That is 20 points.
- **Merged** (`merged/_batch/`): the same five operating points, plus the
  0.25 ohm and 0.5 ohm ESR points at 0 mA/0.33 uF, for both benches. That is
  40 points, run with `--variant-lines` as 2 requests of 20 corners. Each
  `corners.lib` section holds the model cards and then that point's own
  lines.

## Result

All 20 points that both runs share are **byte-identical**
(`per-deck-csv.sha256` against `merged-csv.sha256`). The shared points cover
both benches, ESR = 0 (no resistor line) and ESR = 0.5 ohm (the `Resr` line
moved), and all four corners.

The 1 mA/1 uF/0 ohm loop-gain values also match the committed `#67` record
`20261010-025634-60a3e81.csv` exactly at all four corners:

| corner | PM (deg) | GM (dB) |
|---|---|---|
| ss/125C/res_bcs | 53.871034 | 29.872107 |
| ss/125C/res_wcs | 71.006177 | 23.608484 |
| ff/-40C/res_wcs | 74.817730 | 13.852553 |
| ff/27C/res_bcs | 69.390971 | 23.778005 |

The merged requests took 135 s and 142 s of simulation for 20 corners each.

## Limits

- 20 shared points, not all 384. The remaining DoE points differ only in the
  values on the moved lines.
- Fleet against fleet, ngspice-46 on both sides.
